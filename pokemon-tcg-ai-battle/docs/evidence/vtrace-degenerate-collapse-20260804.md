# 現構成のV-trace学習は発散して停止する（2026-08-04 実測）

## 結論

**現在の構成のまま長時間学習を回してはいけない。** 方策は収集された行動から単調に
遠ざかり、importance ratio が 0 へ潰れて勾配が消え、学習が自動的に停止する。
loss と gradient norm だけを見ていると「収束した」ようにしか見えない。

原因は value head の不在であり、設定調整では解消しない。

## 観測

実収集4,270局に対し `--trajectories-per-step 64` で12ステップ実行した結果:

| step | loss | grad_norm | mean log-prob shift | rho>1.0 |
|---|---|---|---|---|
| 3 | −0.0066 | 0.0334 | −3.52 | 0.056 |
| 5 | −0.0001 | 0.0141 | −5.26 | 0.051 |
| 7 | −0.0008 | 0.0323 | −6.70 | 0.068 |
| 9 | +0.0015 | 0.0118 | −7.39 | 0.044 |
| 12 | +0.0020 | 0.0043 | −7.99 | 0.056 |

最終時点で target log-prob = **−9.60**、behavior log-prob = **−1.61**。
すなわち収集された行動を取る確率が e^-8 ≈ 1/3000 倍まで押し下げられている。

loss は 0 に、gradient norm は 0.004 へ落ちる。これは収束ではなく**信号の消失**である。

## 機構

学習データの reward / value 分布（301局・6,158 transition を検査）:

| 項目 | 実測 |
|---|---|
| `value` | **全件 0.0**（value head が存在しない） |
| `reward` | 0.0 が 5,858、**−1.0 が 272**、+1.0 が 28 |
| terminal | 301/6,158 |

V-trace は `pg_t = rho_t * (reward_t + discount_t * vs_{t+1} - V(x_t))` を使う。
`V(x)` が恒等的に 0 のため baseline が無く、advantage は終端報酬がそのまま伝播した値になる。
勝率が12.6%しかないため、**大多数の transition で advantage が負**になる。

policy loss は `-(advantage * log_prob)` であり、advantage が負のとき勾配は
`log_prob` を**下限なく押し下げる**。log_prob が下がると
`ratio = exp(target - behavior)` が 0 へ向かい、`rho = min(rho_bar, ratio)` も 0 になる。
V-trace は advantage に rho を掛けるため、勾配自体が消える。

つまり方策はデータから逃げ切ったところで学習を止める。到達点は「収集された行動を
取らない」ことだけを学んだ方策であり、良い手を学んではいない。

## 検出手段

この失敗は loss と grad_norm では見えないため、学習側に診断を追加した
（`LearningHealthV1`）。progress bar と集計出力に出る。

- `dlogp` — `mean(log pi_target - log pi_behavior)`。単調に負へ進むなら発散
- `dead_rho` — `rho < 0.01` の割合。0.5 を超えると明示的に WARNING を出す
- `clip_hi` — `rho > rho_bar` の割合。**上側だけを見ると健全に見えるので注意**
  （上記実測で 0.056 と小さいまま発散していた）

## 対処方針（未実施、要判断）

いずれも設計判断を伴うため、実装前に方針を確定する。

1. **value head を実装する**（設計が本来想定している経路）。baseline が入れば
   advantage の符号が状態依存になり、一律の押し下げが起きない。
2. **advantage の正規化または baseline の導入**。minibatch 内で advantage を
   標準化すれば符号が両側に散る。ただしアルゴリズムの変更にあたる。
3. **entropy 項の導入**。現在は係数 0.0 に固定されており、方策の確率質量が
   一点へ潰れるのを防ぐ力が無い。

(要検証) 3案の優劣はローカル実測で比較していない。1が設計正典に沿う。

## この記録の位置づけ

`--max-steps 12` の単一設定・単一seedによる観測である。発散の**方向と機構**は
reward/value 分布から説明できるため確度は高いが、対処後の性能は未測定。

## 追記: value head 実装後の実測（2026-08-04）

設計どおり value head と entropy 項を実装・接続した。**改善は実測できたが、発散は
解消していない。**

### 実測（実収集4,270局、`--trajectories-per-step 64`、60ステップ）

| step | grad_norm | dlogp | dead_rho |
|---|---|---|---|
| 1 | 1.31 | −0.26 | 0.00 |
| 14 | 0.035 | −3.00 | 0.24 |
| 26 | 0.062 | **−1.07** | 0.003 |
| 38 | 0.031 | −4.63 | 0.54 |
| 60 | 0.032 | −6.09 | 0.61 |

value head 導入前は 12ステップで dlogp が −8.0 へ単調悪化していた。導入後は

- **step 26 で −1.07 まで回復している**（導入前には一度も起きなかった）
- 同等の悪化に到達するまでのステップ数が約5倍に伸びた

一方で 60ステップ時点では dlogp −6.09、dead_rho 0.61 となり、WARNING が発火する。
**振動しつつ全体としては悪化する**挙動であり、解決とは言えない。

### 原因の手がかり: critic が較正されていない

critic の予測値と実際の終端収益を出す診断を追加した。smoke corpus 30ステップ:

| step | dlogp | mean V(x) | mean terminal return |
|---|---|---|---|
| 1 | −0.28 | 0.099 | −0.50 |
| 17 | −2.76 | 0.783 | −0.50 |
| 30 | −3.91 | **1.008** | −0.50 |

**V(x) は予測すべき −0.50 から離れて +1.0 へ向かっている。** baseline が収益を
近似していないため、advantage の符号偏りが除去できていない。

有力な仮説は **backbone の共有**である。value head は policy と同じ `encode_state`
の出力を読むため、policy gradient が表現そのものを動かし、critic はその上で
移動する目標を追うことになる。(要検証) 他の候補として value_coefficient=0.5 の
重み不足、学習率 1e-3 の過大、entropy 係数 0.01 の過小がある。

### 次にやること（未実施、方針判断が必要）

1. **critic の分離**: value head に渡す state を detach するか、critic へ独立した
   trunk を与える。policy gradient が critic の入力表現を動かさなくなる
2. **損失の重み調整**: value_coefficient を上げ、critic が先に収束するようにする
   （value warmup を含む）
3. **advantage の正規化**: minibatch 内で標準化し、符号を両側へ散らす

1 が原因仮説に最も直接対応する。いずれも実測で比較していない。

### 運用上の結論

**現時点でも長時間学習は推奨しない。** ただし発散の速度は大幅に遅くなっており、
診断（`dlogp` / `dead_rho` / `V` / `ret`）で状態を判定できる。短時間の実験と
上記1〜3の比較には使える状態にある。

## 解消: BC項の欠落が根本原因だった（2026-08-04）

**発散は解消した。** 原因は backbone 共有でも学習率でもなく、**設計が定める BC 損失を
実装していなかったこと**である。

### 根本原因

policy loss は `-(advantage × log π)` であり、advantage が負のとき **下に非有界**である。
optimizer は log π を下げ続ければ単調に損失を減らせるため、固定コーパスに対する
オフライン学習では、収集された行動の log π が際限なく下がる。その結果 ρ→0 となり、
V-trace は advantage に ρ を掛けるため勾配が消えて学習が停止する。

設計は 235行目で **「Policy/value/entropy/BC losses」** を recipe として定め、321行目で
`rule_bc_vtrace` を挙げている。また V-trace の前提を「importance ratios correct subject
behavior lag *only*」と明記している。すなわち**方策が behavior の近傍に留まること**が前提
であり、プールを更新できない固定コーパスではそれを保証する項が要る。BC 項がその錨である。

前回の仮説（backbone 共有）は**誤り**だった。計測すると V は +1.0 へ「発散」していたのではなく
−0.90 ↔ +1.05 で**振動**しており、`mean_vs ≈ mean_V`（δ≈0、advantage は 0.01〜0.04 と極小）
であった。方策の暴走が先で、critic の未較正はその結果である。

### 係数スイープ（実収集データ、40ステップ）

| `bc_coefficient` | dlogp @ 0 / 10 / 20 / 30 / 39 |
|---|---|
| 0.0 | −0.13 → −1.49 → **−4.66** → −3.12 → −2.30（発散） |
| **0.1** | −0.13 → +1.21 → +1.34 → +1.51 → **+1.57**（安定） |
| 0.5 | −0.13 → +1.57 → +1.76 → +1.79 → +1.80（飽和） |
| 1.0 | −0.13 → +1.65 → +1.78 → +1.80 → +1.80（飽和） |

0.5 以上では rule agent の純粋な模倣に飽和し、policy gradient が方策を動かせなくなる。
**0.1 を既定とする**。安定かつ RL 項が効く余地が残る実測点である。

### 実収集4,270局・80ステップでの確認

| step | grad_norm | dlogp | dead_rho | V | ret |
|---|---|---|---|---|---|
| 1 | 0.86 | −0.26 | 0.000 | +0.195 | −0.81 |
| 24 | 1.28 | +1.16 | 0.000 | −0.878 | −0.69 |
| 47 | 1.17 | +1.29 | 0.001 | −0.497 | −0.72 |
| 70 | 1.20 | +1.36 | 0.000 | −0.865 | −0.78 |

最終: dlogp **+1.4188（収集行動へ接近）**、dead_rho **0.000**、80ステップ完走・
skipped 0・scoring failure 0、WARNING 非発火。

**critic も同時に較正された。** V が ret（≈−0.78）を追うようになっている。方策の暴走が
ρ を潰し、value loss から信号を奪っていたためであり、原因を除いた結果 critic は
手を加えずに直った。前回挙げた対処案1〜3はいずれも不要だった。

### 残る注意点（発散とは別問題）

- `clip_hi = 0.866`。方策が rule agent より決定的になったため ρ>1 が多数を占め、
  V-trace が上側で clip している。ρ→0 と違い勾配は失われないため退化ではないが、
  off-policy 補正が上限に張り付いている状態ではある。
- bc_coefficient 0.1 に対し |advantage| は 0.01〜0.04 であり、**BC 項が policy gradient を
  およそ3倍上回る**。現状は「わずかに RL で傾けた模倣」であり、RL 由来の改善幅は小さい。
  advantage を大きくするには終端報酬の希薄さ（terminal は全 transition の約5%）に
  対処する必要がある。(要検証) これは発散とは独立の課題である。
