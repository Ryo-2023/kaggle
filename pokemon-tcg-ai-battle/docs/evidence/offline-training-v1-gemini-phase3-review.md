# Offline Training v1 Support Platform Phase 3 Code Review Report

本報告書は、Phase 3 開発を通じて追加・強化したモジュール群に対する、第三者レビュー視点でのコード監査と堅牢性（Hardening）の評価記録です。

## 1. 既存モジュールの脆弱性監査と修正 (Milestone 1)

### 1.1 `contracts.py` (入出力と排他制御)
- **問題点**: JSON シリアライズ時の float 特異値 (`-0.0`) や Unicode 非正規化、64bit整数オーバーフローの許容。また `fsync` 漏れや `lock` 衝突時のゾンビロック残留。
- **防御策**:
  - `walk_safe` で `-0.0` 検出時に `SupportContractError` を投げ拒否。Unicode 文字列は NFC 規格化チェックを強制。
  - `atomic_write_json` / `atomic_write_records` において、`fsync(f.fileno())` および親ディレクトリの `fsync` を実行してOSディスクバッファのフラッシュを保証。テンポラリファイルは `finally` ブロックで確実に削除。
  - `FileLock` において、`os.kill(pid, 0)` を使った PID 生存確認を導入。さらにホスト名検証を加え、自身のロックファイルのみを安全に解除するよう堅牢化。

### 1.2 `registries.py` (データセット/モデル/実験/デッキレジストリ)
- **問題点**: モデルの不正な状態遷移（例: `ARCHIVED` -> `ACTIVE`）の抑止力不足、成果物間の循環参照（Lineage Cycle）検出の欠落。
- **防御策**:
  - 状態遷移マトリクスを定義し、許可されない状態遷移を検知した場合は `SupportContractError` で遮断。
  - 成果物の親関係（`parents`）に自身が含まれていないかを DFS（深さ優先探索）により循環参照検出するガードを挿入。

### 1.3 `statistics.py` & `ratings.py` (統計とレーティング)
- **問題点**: ブートストラップサンプリングにおける入力順序依存性。自己対戦時の Elo 計算上書きバグ。Bradley-Terry 計算時の数値アンダーフロー。
- **防御策**:
  - サンプリング前にデータを `game_id` / ハッシュで決定論的にソート。
  - 自己対戦時は Elo 更新処理をスキップ。
  - BT の MM アルゴリズムに `max(1e-12, ...)` の最小境界クリップを適用し、数値的不安定性を完全に解消。

## 2. 統合・分析モジュールの追加 (Milestone 2)

### 2.1 互換性 & 移行プラン (`compatibility.py`)
- **問題点**: スキーマ定義の破壊的変更（Required フィールドの追加、型の不一致など）を検知できない問題。
- **防御策**:
  - A から B への移行可否をチェックし、非互換であれば Markdown 形式の具体的な「移行プラン」を提示する仕組みを導入。

### 2.2 有意差・多重比較補正 (`comparison.py`)
- **問題点**: 多数のポリシー間の比較で第1種のエラー（False Positives）が膨らむ問題。
- **防御策**:
  - SciPy 非依存で Holm-Bonferroni 多重比較補正を完全実装。多対一の比較でも有意水準を正しく制御可能に。

### 2.3 Pareto 候補分析 & 安全 limits (`candidate_analysis.py`)
- **問題点**: 勝率が良いがクラッシュ率や遅延が最悪の「不安全なモデル」が選ばれてしまうリスク。
- **防御策**:
  - Win Rate (higher), Latency (lower) などの方向性（`METRIC_DIRECTIONS`）に基づく多目的最適化 Pareto 選択と、クラッシュ率などの `safety_limits` による安全フィルターを連結。

## 3. 監査・トレーサビリティ・セキュリティ (Milestone 3)

### 3.1 ハッシュチェーン監査ログ (`audit_log.py`)
- **問題点**: 過去の操作ログが改ざんされたり、途中のイベントが欠落するリスク。
- **防御策**:
  - 各操作イベントを SHA-256 ハッシュ値で鎖状（Hash Chain）に連結。以前のハッシュ値を次のイベントの `prev_hash` に含めることで、中間の削除や書き換えを確実に検知。

### 3.2 循環検出 Lineage DAG (`lineage.py`)
- **問題点**: データとモデルの依存関係が追跡できず、再現性が失われる問題。
- **防御策**:
  - `VALID_NODE_TYPES` と `VALID_EDGES` を定義し、DFS による閉路（Cycle）検出を搭載した Lineage DAG を実装。DOT 形式および Markdown 形式での可視化に対応。

### 3.3 設定 linter (`config_lint.py`)
- **問題点**: 訓練実行前に不適切なパラメータや絶対パスが含まれ、実行時エラーになる問題。
- **防御策**:
  - `seed` 欠落チェック、スプリット比率の合計値検証（`== 1.0`）、およびローカル絶対パスの検出・警告。
